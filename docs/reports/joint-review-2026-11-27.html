代码与跨仓契约

P1　平台待核查任务在 MV 可被当作普通失败

平台将 manual_review 序列化为 failed，账务状态另行返回。对提交结果不确定且自动重发已封锁的样本，常规 MV 轮询按 FAILED 抛出普通 ProviderError；任务执行器据此写为 failed。若错误正文也未命中本地中文关键字，retryAllowed 可恢复为 true。用户发起新意图后会获得新的幂等键，有重复生成或预占风险。原视频恢复流程已经检查最终结算，两条入口的判定不同。

建议　平台保留既有公开 status，增加明确的待核查标记。MV 的首次轮询、手动查询和自动恢复共用终态判断。旧平台响应无法证明最终失败时保留原工单并查询，继续展示待核账。

验收　合成一次“供应商提交结果不明、账务待核查”。从平台响应走到 MV 聚合查询和浏览器刷新，断言 retryAllowed=false、创建调用仍为一次。再送达已确认失败及最终结算，验证只有这时允许新意图。

P1 · 配置相关　视频交付要求两个服务使用同一 OSS 桶及特定域名

平台允许 OSS_PUBLIC_DOMAIN 自定义结果域名。MV 只接受按自身桶名和区域拼出的公网主机，复制操作也固定从本桶取源对象。MV 部署手册同时描述独立桶和共桶。使用独立桶或自定义域名时，即便平台已生成且归档成功，当前视频路径也无法交付。自动核对仍用同一套校验，重试不能消除配置差异。

建议　先明确支持的部署组合。若只支持共桶标准域名，在发布前用两端有效配置及无费用的归档样本验证并阻断不兼容发布。若要支持独立桶或自定义域名，由平台交付受验证的源桶、对象键及归属，MV 仅允许同环境白名单内复制。将日志区分为清单无效、源不可读和复制失败。

验收　测试环境分别覆盖共桶标准域、同桶别名、独立桶、其他工单对象和临时复制失败。受支持的组合能交付三件素材；不支持的组合在受理用户生成前可发现。

P2　场景图去重发生在上传参考图之后，且不同参数可返回同一工单

同一镜头有活动或待核查图片工单时，MV 按用户和镜头返回原工单。判断之前已为内联参考图分配对象键并写原图和缩略图。带内联图重试会产生本次工单未引用的新对象；修改提示词或图像模型后也可能收到旧工单的 202。

P2　素材包一个分片上传失败后仍可能读完整批视频

Go helper 异步上传分片，上传结果放入 finished；所有源文件处理完、所有上传结束后才检查各分片 Failure。首片收到错误且后续 GET 正常时，大素材包仍会继续下载和上传。Python 外层会撤销失败分片，主要损失是流量、等待时间与导出槽位。另有混合来源情况：只要一个条目来自历史 TOS，整个包进入 Python 下载分支。

建议　先让首个分片错误通知读循环并取消新的 GET/PUT，回收已经在途的请求后统一 abort。分别统计纯 OSS 与混合包的读取字节和耗时，再决定是否按条目选择传输路径。

验收　用本地 HTTP 替身令第一片 PUT 失败，记录剩余 GET 次数、退出时间、abort 次数；成功路径仍需能解压 ZIP 并逐项核对内容。
