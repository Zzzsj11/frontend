# 视频待人工核对

供应商提交超时、响应不可确认等情况不能等同于确定失败。`manual_review` 保留原工单与费用证据，用户界面显示“待人工核对 · 不能重新生成”，提示联系开发人员并提供复制工单信息。单镜、详情及批量入口均拦截，服务端提交返回 409；聚合查询返回 phase 和 retryAllowed，刷新恢复一致。

管理员在生成任务中筛选“待人工核对”。已有平台工单号的任务使用同步入口核查原任务；没有平台工单号且经平台确认未受理的失败任务，填写核查依据并确认后可解除重试限制。API 为 `POST /api/admin/jobs/{id}/release-review`，仅超级管理员可操作。活跃、已受理、已解除及已删除任务不能解除。操作与原状态写入审计日志及工单请求快照，不自动生成、不修改费用、不删除记录。

用户刷新后可手动重新生成，新意图创建新工单；原请求重放仍保持幂等。生成返回 409 后清理客户端未确认的请求标识，避免解除后继续复用旧意图。正常网络异常保留原标识。

验证：`backend/tests/test_video_submission_recovery.py`、`e2e/user/manual-review.spec.ts`，发布前执行完整 preflight。远程验收仅在测试环境创建隔离、带 Agent 归因的合成待核对工单，不调用供应商；验收后软删除。

## 已受理原视频自动恢复

all in one 已有平台任务 ID 的超时／待核对视频由 API 生命周期中的独立巡检恢复。持久化 `reconciliation_next_at` 和次数，数据库行锁领取、180 秒租约、30 秒心跳及归属校验，两个恢复槽位不占生成 Worker。进程退出后租约过期自动接管。首次立即查询，此后 60 秒起指数退避，最多 15 分钟一次；平台仍在归档、网络或下载失败会继续核对。该路径仅 GET 原平台任务，不调用创建、重新生成、预占或平台结算接口，沿用原用户及 Agent 归因。

界面显示“正在自动核对并恢复原视频，无需重新生成，不会重复扣费”，持续观察原工单；刷新可恢复观察。服务端继续拦截单次与批量重提。没有平台任务 ID 的不确定提交仍走人工核对流程；已受理任务不能人工解除后重提。

成功时导入 TOS 原视频和封面，锁定原工单，原素材按工单去重；素材、用量更新、MV 对账记录与成功状态在同一事务落库。旧视频晚到时保存历史资产，不替换后续工单的当前视频。平台失败或计费证据不明确时继续阻止重复生成，不自动推断退款。管理员同步已受理待核对任务共用领取及恢复流程，避免并发回填。

测试：`backend/tests/test_video_reconciliation.py` 覆盖原 ID 查询、重提拦截、租约过期恢复与旧进程隔离、网络/归档失败退避、删除隔离、事务回滚及新旧版本保护；`e2e/user/video-reconciliation.spec.ts` 验证自动恢复提示及前端拦截。
